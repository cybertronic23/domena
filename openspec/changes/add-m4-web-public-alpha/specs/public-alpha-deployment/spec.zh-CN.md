## 新增需求

English version: [spec.md](spec.md)

### 需求：可复现单节点部署
项目必须提供带文档和版本的单节点部署，其中包含 Web 应用、Go API、Python Worker、PostgreSQL、兼容 S3 的对象存储和 Ray Runtime。部署必须初始化数据库迁移并暴露健康/就绪状态，且不要求 Kubernetes。

#### 场景：启动全新部署
- **当** 运维者按文档配置必需秘密并启动部署
- **则** 迁移只完成一次，服务按依赖顺序就绪，并能够提交参考工作流

### 需求：安全且有界的数据访问
部署必须执行认证、工作空间授权、上传大小/类型策略、受限对象授权、秘密隔离和资源配额。日志和 API 错误不得暴露凭据或带签名对象 URL。

#### 场景：未授权对象请求
- **当** 用户请求无权访问工作空间的对象
- **则** 服务不返回对象授权，并记录脱敏审计事件

### 需求：运行证据与恢复
请求与任务必须通过 Go 和 Python 日志携带关联 ID。部署必须提供结构化日志、任务/attempt 状态、健康检查，以及 PostgreSQL 备份恢复和对象引用对账文档。组件重启不得将未经验证的 attempt 变成成功。

#### 场景：执行过程中 API 重启
- **当** Go API 在 Worker 持有有效租约期间重启
- **则** 已持久化任务状态继续作为权威，Worker 可以恢复心跳或按租约策略过期

### 需求：Public Alpha 发布门禁
只有在全新受支持环境中完成浏览器驱动的 ROS 2 MCAP 到 Lance 工作流、质量报告检查、取消/失败诊断、工作空间隔离测试和备份/重启冒烟测试后，才能发布 Public Alpha。产品必须明显标识 Alpha，并说明 API 在 1.0 前可能变化。

#### 场景：发布门禁失败
- **当** 任一强制端到端、隔离或恢复检查失败
- **则** 该版本不得作为 M4 Public Alpha 推广
