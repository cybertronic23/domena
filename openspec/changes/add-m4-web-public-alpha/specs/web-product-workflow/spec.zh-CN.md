## 新增需求

English version: [spec.md](spec.md)

### 需求：Web 优先的 Source-to-Release 工作流
Web 产品必须让授权用户在不使用 CLI 或 Python 的情况下，注册或上传 ROS 2 MCAP 数据源，检查 Topic 和时间范围，将完整数据源定义为一个 Episode 或定义多个显式左闭右开 Episode 区间，校验计划、提交处理并检查生成的不可变 Dataset Release。

#### 场景：导入单 Episode
- **当** 用户选择将完整数据源作为一个 Episode 并提交有效计划
- **则** 产品展示数据源、生成的 Episode 身份、处理任务和已发布 Release 血缘

#### 场景：导入多个显式 Episode
- **当** 用户提供互不重叠的显式 `[start, end)` 区间及 Episode ID
- **则** 产品预览并保存这些边界，不进行启发式切分

#### 场景：无效切分计划
- **当** 区间为空、互相重叠或超出数据源范围
- **则** 产品阻止提交并指出无效边界

### 需求：产品中可见的可复现性
Dataset Release 和任务页面必须按需展示数据源身份、Episode 复合身份、Release 指纹、处理/算子版本、确定性配置、engine/runtime、物化引用、质量证据和父级血缘。

#### 场景：检查 Release
- **当** 用户打开已发布 Release
- **则** UI 展示其不可变指纹、成员数量、来源/父级血缘、生产任务和物理物化信息，不把可变路径当作 Release 身份

### 需求：可操作的任务诊断
Web 产品必须显示当前控制面状态、当前 attempt、时间、可用进度、是否可取消及脱敏失败证据。用户错误必须保留稳定错误码和关联 ID，同时排除凭据和内部秘密。

#### 场景：处理失败
- **当** Worker 上报终态失败证据
- **则** 任务页面显示失败代码、可操作消息、attempt 历史和关联 ID，且不展示成功 Release

### 需求：共享 API 语义
浏览器、CLI 远程模式和外部客户端必须使用同一带版本控制面 API。除 API 发放的受限上传/下载 URL 外，Web 客户端不得直接调用 Ray、Python Worker、PostgreSQL 或对象存储。

#### 场景：浏览器上传数据源
- **当** Web 客户端请求上传
- **则** API 检查工作空间权限、创建对象登记，并只返回有界且限定范围的上传授权
