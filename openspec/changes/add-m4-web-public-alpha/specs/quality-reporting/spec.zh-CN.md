## 新增需求

English version: [spec.md](spec.md)

### 需求：带版本、可复现的质量报告
数据面必须生成绑定 Episode 或 Dataset Release 指纹的带版本质量报告。每个指标必须标识算子 ID/版本和确定性配置指纹。对等价不可变输入和配置重新生成报告时，除明确声明的易变元数据外，必须产生等价指标证据。

#### 场景：生成 Episode 报告
- **当** 使用受支持质量算子集合评估有效 Episode
- **则** 报告记录源指纹、算子版本、配置指纹、指标证据、问题和生成元数据

### 需求：M4 最小质量证据
第一版报告必须支持通道存在性、Step/时间覆盖、时间戳单调性、观测采样率、时间间隙、Episode 时长和现有契约校验问题。不支持的模态专用检查必须明确标识，不得报告为通过。

#### 场景：必需通道缺失
- **当** 策略声明某通道为必需，但 Episode 中不存在该通道
- **则** 报告包含带通道身份和支持计数的缺失通道问题

#### 场景：检查不受支持
- **当** 配置的检查无法评估源表示
- **则** 报告将检查标为不支持，且不计为通过

### 需求：先保留证据，再应用策略结论
质量指标和问题必须与带版本质量策略结论分离。策略必须标识阈值和版本。策略变化不得修改已有指标证据。

#### 场景：使用新策略重新评估
- **当** 同一报告证据使用更新阈值策略进行评估
- **则** 系统记录链接到同一证据的新结论，不重写原始报告

### 需求：Release 聚合与失败切片
Dataset Release 质量报告必须在不隐藏成员级结果的前提下聚合 Episode 证据，并支持确定性失败切片，标识成员复合身份以及选择它们的策略/检查。

#### 场景：检查聚合失败
- **当** Release 级指标指出存在失败成员
- **则** 用户可以导航到选中的 Episode 身份及其支持证据
