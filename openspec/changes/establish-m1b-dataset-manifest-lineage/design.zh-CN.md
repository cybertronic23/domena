## 背景

JD 调研持续强调：数据集版本、血缘、快速切片、质量证据、实验对比和由失败驱动的再采集。M1a 有意停留在已校验的 Episode 边界；M1b 应在不预设数据湖、查询引擎、标注供应商、对象存储提供方或训练框架的前提下，增加可复现的数据集组装能力。

## 目标与非目标

**目标**

- 让数据集成员关系在本地文件系统中显式、不可变、可检查且可复现。
- 保存从数据集发布版本到 Episode 标识、Episode 指纹、来源引用、M1a 模式版本及声明构建输入的追溯链。
- 让未来实验和失败报告能够指向某一数据集发布版本与 Episode/Step 范围，而不耦合模型运行器。
- 区分数据身份与存储位置，避免清单迁移时其含义发生静默变化。

**非目标**

- 不实现查询服务、Web UI、向量检索、云注册表、湖仓、分布式执行或机器人群数据接入。
- 不实现质量评分算法、标注 UI、主动学习策略、训练/推理系统或基准评测运行器。
- 不自动解析 ROS bag、仿真文件、媒体资产或远程 URI。
- 不引入来源专属的数据划分约定或具身形态专属的数据集格式。

## 拟议设计

### 1. 将不可变清单作为数据集发布版本单元

持久化单元为 JSON 兼容的 `DatasetManifest`，初步模式名为 `domena.dataset-manifest/v0.1`。清单表示一个精确发布版本，而不是可变目录或已保存查询。

其拟包含：

- 人类可读的 `dataset_name` 和可选逻辑血缘名称；
- 发布版本标识与规范化 SHA-256 内容指纹；
- 支持的经验数据模式版本；
- 每个 Episode 的显式有序成员条目；
- 包含生成器版本、选择理由、输入与时间戳的 `construction` 记录；
- 可由成员关系重新计算的汇总统计；
- 可选划分标签与不透明扩展字段；
- 对质量、评测和失败证据的引用，但 M1b 不解释这些证据。

### 2. 显式成员关系，而非动态选择

每个成员记录 `source_namespace_id`、`episode_id`、必填 SHA-256 Episode 指纹，以及足供本地消费者解析序列化 M1a Episode 的定位符/引用。`(source_namespace_id, episode_id)` 的组合构成成员身份；裸 `episode_id` 不要求全局唯一。成员关系会被物化到发布版本中；查询或筛选配方可以作为溯源保存，但不能成为重建成员关系的必要条件。

`source_namespace_id` 是内部注册的稳定数值 ID。清单同时保存该 ID 与可读来源命名空间字符串快照。注册表可以为未来数据调整命名，而不会使历史发布版本失去可解释性。

如此即使源目录后续加入新 Episode，或筛选逻辑发生变化，数据集仍保持稳定。

### 3. 区分身份与指纹

草案区分两类概念：

- **逻辑身份**：人类有语义的名称，例如 `tabletop-pick-v1`；
- **发布版本指纹**：对规范化清单内容计算的确定性摘要，用于检测成员关系或声明兼容性变化。

发布版本指纹对规范化后的语义内容计算 SHA-256：有序成员身份及 Episode 指纹、划分标签、受支持经验数据模式版本，以及必要的转换/兼容配置。它排除创建时间、作者、自由文本描述和备注等易变元数据。因此，在不同时间重建的等价发布版本会得到相同指纹。

每个 M1b 成员必须具有 Episode 内容指纹。M1a 将为规范化 Episode JSON 提供稳定 SHA-256 指纹，确保内容变更的 Episode 不会在数据集发布版本中静默沿用原身份。

### 4. 将溯源作为声明性证据

清单溯源采用不可追加的发布记录，描述此版本的构建方式：M1a 契约版本、父清单/父发布版本（如有）、选择配方引用或文字理由、工具/版本身份，以及声明的质量或策展证据引用。

M1b 记录溯源，但不保证远程 URI 持续可访问，也不验证引用的质量报告是否真实。

### 5. 兼容性与校验

M1b 校验应是结构化且本地化的：

- 必填 ID 存在且唯一；
- 每个成员都具有受支持的 M1a 模式版本和合法指纹格式；
- 划分标签、扩展字段和溯源引用遵循文档化规则；划分标签是可选成员元数据，而非一等划分对象；
- 汇总计数与声明成员关系匹配；
- 若提供发布版本指纹，其必须与规范化内容匹配。

M1b 保证本地相对路径解析可用。它可以保留其他 URI 作为不解释的来源引用，但不引入通用 URI 解析协议。可选的本地解析可以验证被引用 Episode 文件可读取，且其 ID/指纹与成员信息一致；URI 可达性与大资产检查独立于核心清单校验。

### 6. 评测与失败关联边界

M1b 只定义稳定引用：评测或失败记录可标识 `dataset_release`、`source_namespace_id`、`episode_id` 及可选 Step 区间。质量、标注与失败证据使用一个小型共享证据引用类型，包括 `kind`、稳定外部 `id` 与可选 `uri`；M1b 不解释证据内容。不定义指标模式、评分、失败分类、看板行为或模型执行；这些属于 M3 或后续获批变更。

## 候选本地工作流

1. 校验并序列化 M1a Episode，再计算其规范化 SHA-256 指纹。
2. 选择有限的 Episode 引用列表。
3. 基于显式列表构建并校验清单。
4. 将规范化清单写入本地并计算发布版本指纹。
5. 按需检查清单、解析本地 Episode 引用，并将发布版本 ID 交给未来训练/评测工具。

## 已确认决策

1. 数据集成员身份为 `(source_namespace_id, episode_id)`；内部来源命名空间维护稳定数值 ID 到字符串枚举的注册表，清单保留两者。
2. 发布版本指纹对语义内容计算 SHA-256，并排除易变元数据。
3. 每个成员必须包含 SHA-256 Episode 内容指纹，由 M1a 的规范化 JSON 指纹能力提供。
4. train/validation/test 在 M1b 保持为可选成员级标签。
5. M1b 只支持本地相对路径解析；其他 URI 可以保留但不解析。
6. M1b 为质量、标注、评测与失败引用引入最小共享证据引用类型。
7. 验收使用一个经过策展的本地 M1a JSON Episode 目录，而非仅用内存 mock 对象。
