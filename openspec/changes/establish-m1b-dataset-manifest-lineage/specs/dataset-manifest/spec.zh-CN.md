## 新增需求

英文版本：[spec.md](spec.md)

### 需求：稳定的来源命名空间注册表

系统必须使用正整数 `source_namespace_id` 和非空字符串 `source_namespace` 表示每个数据集成员的来源。`DatasetManifest` 必须嵌入每个成员数值 ID 所对应的字符串快照；数值 ID 是该清单内的稳定身份，单独的 `episode_id` 不得被视为全局唯一。

#### 场景：区分来自两个来源的相同 Episode ID

- **当** 两个成员使用相同的 `episode_id`、但 `source_namespace_id` 不同
- **则** 校验接受两个成员，并将其组合身份视为不同成员

#### 场景：拒绝冲突的命名空间快照

- **当** 两个成员使用同一个 `source_namespace_id`、但 `source_namespace` 字符串不同
- **则** 校验返回可定位到路径的命名空间注册表冲突

### 需求：显式且不可变的成员列表

系统必须提供由 `domena.dataset-manifest/v0.1` 标识的不可变 `DatasetManifest` 契约。清单必须包含非空的数据集名称、发布 ID、支持的经验模式版本，以及显式、有序、有限的 Episode 成员列表。每个成员必须包含组合身份、SHA-256 Episode 内容指纹，以及本地相对定位符或不解释的外部定位符。

#### 场景：保留有限的本地数据集发布

- **当** 调用方以有限有序的 M1a Episode 引用列表创建清单
- **则** 序列化保留精确的成员顺序、身份、指纹、定位符及兼容性声明，而不执行实时查询

### 需求：规范化发布指纹

系统必须从规范化的语义清单内容计算小写 SHA-256 发布指纹：有序成员身份与 Episode 指纹、成员 split 标签、支持的经验模式版本及必要兼容配置。创建时间、作者元数据、自由文本描述和备注不得影响该指纹。

#### 场景：忽略易变的创建元数据

- **当** 两个其他内容等价的清单仅创建时间或自由文本备注不同
- **则** 其计算出的发布指纹相同

#### 场景：发现成员变更

- **当** 一个成员的 Episode 指纹或 split 标签发生变更
- **则** 计算出的发布指纹改变，且校验拒绝不匹配的声明发布指纹

### 需求：结构化本地校验

系统必须对不支持的模式标识、格式错误的 SHA-256 指纹、重复的组合成员身份、缺失的本地相对定位符、无效 split 标签、无效扩展键、无效证据引用及不匹配的成员聚合计数返回可定位到路径的校验问题。

#### 场景：拒绝重复成员身份

- **当** 一个清单包含两个具有相同 `source_namespace_id` 和 `episode_id` 的成员
- **则** 校验返回重复成员所在路径

### 需求：本地引用解析边界

系统只能相对于调用方提供的清单目录解析本地相对成员定位符；必须将非本地 URI 保留为不透明引用，且不得尝试网络访问或来源适配器解析。

#### 场景：在本地解析已序列化的 M1a Episode

- **当** 成员引用本地相对路径的 M1a JSON 文件且请求解析
- **则** 系统读取本地 Episode，并对其 Episode ID 与规范化 SHA-256 指纹和成员声明进行校验

#### 场景：保留远端 URI 而不解析

- **当** 成员包含 `s3://` 或其他非本地 URI
- **则** 清单校验保留该定位符且不进行网络访问

### 需求：证据引用与成员级 split 标签

系统必须支持可选成员 split 标签，且其值仅限 `train`、`validation` 和 `test`。系统必须支持来源无关的证据引用，其中包含非空 `kind`、稳定 `id` 和可选 `uri`，但不解释质量、标注、评测或失败证据的语义。

#### 场景：将失败报告关联至成员

- **当** 清单为成员或发布包含失败证据引用
- **则** 序列化与校验保留其 kind、ID 和可选 URI，而无需失败分类体系
