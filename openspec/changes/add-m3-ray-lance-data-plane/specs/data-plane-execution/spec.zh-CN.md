## 新增需求

### 需求：不可变的有界处理计划
系统必须用输入 DatasetManifest 的 Release 指纹、带版本的处理标识、确定性配置和显式输出模式标识表达有界处理计划。输入 Manifest 的声明 Release 指纹校验失败时，系统必须拒绝该计划。

#### 场景：构造有效计划
- **当** 调用者提供有效的不可变 Manifest 和受支持的确定性处理声明
- **则** 系统创建可检查输入与处理指纹的计划

#### 场景：拒绝无效输入 Release
- **当** 调用者提供 Release 指纹无效的 Manifest
- **则** 系统在执行开始前拒绝构造计划

### 需求：与执行器无关的任务运行记录
系统必须公开不可变任务运行记录，其中包含逻辑处理引擎 `engine_name`、执行运行时 `runtime_name`、状态、输入 Release 指纹、处理指纹、时间和可选失败证据。成功运行必须拥有物化引用；失败或取消运行不得拥有物化引用。

#### 场景：记录成功执行
- **当** 执行器完成 staging 输出校验
- **则** 系统记录带物化引用的成功运行

#### 场景：记录失败执行
- **当** 执行器遇到处理或校验失败
- **则** 系统记录失败证据且不发布物化引用

#### 场景：分别识别处理引擎与运行时
- **当** 处理引擎运行在单独选择的执行运行时上
- **则** 任务运行记录分别标识两者，例如 `engine_name=daft`、`runtime_name=ray`

### 需求：有界执行器扩展契约
系统必须公开最小执行器契约：接收 `TransformPlan` 与显式执行选项，返回 `JobRun`。该契约不得暴露引擎特定的算子图或优化器设置。本地执行器和 Ray Data 执行器必须实现这一契约；未来的 Daft 执行器必须能够在不改变计划、任务运行记录、指纹、staging 或物化发布语义的前提下实现它。

#### 场景：增加未来执行器且不改变 Release 语义
- **当** 后续为已支持计划增加 Daft 执行器
- **则** 它可以报告 `JobRun`，且只能以相同的 Domena Release 身份和校验规则发布经验证的物化引用

### 需求：本地与 Ray Data 执行一致性
系统必须为同一受支持有界处理计划提供确定性的本地执行器和可选 Ray Data 执行器。Ray 集成必须延迟导入，且缺少可选依赖时必须给出可操作的依赖错误。

#### 场景：本地执行受支持计划
- **当** 调用者向本地执行器提交受支持计划
- **则** 系统产生确定性行和终态任务记录

#### 场景：通过 Ray Data 执行同一计划
- **当** 已安装 Ray，调用者向 Ray 执行器提交同一受支持计划
- **则** 输出规范行与计划指纹和本地执行结果一致
