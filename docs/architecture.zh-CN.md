# 架构

[English](architecture.md)

## 当前方向

Domena 是 Python-native 数据平面。第一个交付物是在本地 CPU 环境中打通从 Mock Source 到校验、序列化数据集、读取和检查的路径；该路径必须有价值，同时不能让核心依赖 Mock Source。

```text
Source / Adapter Layer（来源 / 适配器层）
                 ↓
Experience Layer（经验层）
                 ↓
Validation and Processing（校验与处理，数据平面）
                 ↓
Dataset / Storage Layer（数据集 / 存储层）
                 ↓
Training and Evaluation Consumers（训练与评估消费者）
```

### 来源 / 适配器层

来源包括模拟器、真实机器人和遥操作系统。适配器负责来源特有的生命周期、术语、载荷解码、时钟语义，以及到 Domena 所有边界契约的转换。核心不得导入或暴露 ManiSkill、SAPIEN、Isaac Sim、MuJoCo、Gazebo 或机器人 SDK。

### 经验层

Experience 是交互产生信息的一等领域概念，指导系统词汇和不变量；它并不等同于某个文件、行或消息，也尚未承诺为单一持久化对象。v0.1 数据边界仍由经验 Schema 规范决定。

### 数据平面

Python 数据平面负责校验、仅在通用不变量需要时进行规范化、转换数据并构建数据集。它必须保留足够溯源信息，同时不将来源内部细节变成通用模型的一部分。

### 数据集与存储层

数据集构建与存储是不同关注点。存储表示服务于持久化和读取，可独立于领域契约演进；当前不选择具体存储引擎。

### 消费者

训练与评估通过稳定的读取、检查接口消费数据集。它们是下游消费者，而不是核心依赖。

## 依赖方向

核心领域契约处于中心。校验、处理、存储和适配器可以依赖它；具体适配器与后端不能被核心导入。应用层负责组装具体实现。

## 刻意不包含的部分

当前没有 Go 服务、Web UI、数据库要求、调度器、分布式运行时、认证系统或云端部署拓扑。未来 Go 控制平面可能管理注册表、任务、元数据或 API，但它不在最初里程碑内，并且应当与 Python 数据平面对接而非替代它。

## 待重新审视的决定

- Schema 与数据集的版本和兼容策略。
- 规范存储表示及媒体资产布局。
- 是否将持久化 Episode 作为 v0.1 交换单元。
- 跨来源所需的最小溯源与时间模型。
