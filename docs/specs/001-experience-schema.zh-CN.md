# 规范 001：Experience Schema v0.1

[English](001-experience-schema.md)

**状态：** 提议中——实现前须完成架构评审。

## 范围

定义最小的、来源无关的契约，用以将有边界的交互轨迹从 Mock Source 经由校验、本地序列化、读取和基础检查完整传递。规范将决定该契约是否为 Episode，并定义最小身份、顺序、模态值/引用、结果、溯源和扩展机制。

## 要求

- 在 Python 3.11+ 中以显式类型提示实现，不依赖 GPU、网络服务或具体模拟器。
- 保留有序交互数据，支持可选观察、动作、状态、反馈、时间戳和元数据，而不要求每个模态都存在。
- 能表示或引用常见多模态值，不规定张量库或存储引擎。
- 将通用概念同来源特有载荷和适配器分离。
- 定义结构校验不变量、可操作的校验错误，以及来源/任务特有校验规则的扩展路径。
- 定义带版本的序列化信封和读写往返期望，但不提前选择列式、数据库或媒体后端。
- 允许基础轨迹与模态统计，且不依赖训练代码。

## 非目标

- 通用机器人本体论、模拟器 API 或真实机器人协议。
- 覆盖所有概念和模态的固定 Pydantic 层次。
- 分布式摄取、云存储、注册服务、用户认证或数据集版本管理。
- 训练、评估、回放或可视化框架。
- ManiSkill 适配器，或 Mock Source 之外的具体来源实现。

## 领域边界

Schema 必须说明哪些元素是领域概念、公共契约/协议、值对象、校验结果和存储表示。不得将内存领域对象等同于磁盘表示：适配器输入归来源所有，序列化信封归存储所有，只有获批契约属于 Domena Core。

## API 期望

后续实现应暴露小型、来源无关的方式来构造或流式传递有边界轨迹、进行校验、本地序列化、读取和检查。公共 API 应审慎接受扩展数据，不能泄漏无类型来源载荷；具体名称和类选择留待本规范获批后决定。

## 校验要求

至少覆盖 Schema 版本识别、必需标识符、顺序/唯一性规则、提供时间戳时的时间一致性、模态引用完整性，以及已声明终止/结果数据的一致性。错误必须指出轨迹与位置。质量阈值和模拟器/任务语义仍为可插拔规则。

## 序列化要求

v0.1 格式必须本地可用、对测试具有足够确定性、携带显式 Schema 版本、保留扩展数据，并在不静默丢失受支持值/引用的情况下读写往返。大二进制媒体不得迫使我们过早选型；设计必须说明其处理方式或明确将其排除在首个实现之外。

## 测试要求

测试须在 macOS 本地运行，无 GPU 和外部服务。覆盖有效 Mock 轨迹、遗漏可选模态、错误顺序、无效终止信号、不支持的版本、扩展保留和读写往返。真实适配器存在后，增加适配器隔离测试。

## 验收标准

架构评审批准数据边界、最小必填字段、时间模型、扩展策略和存储信封。随后的实现能够演示：

1. Mock Source 生成有效样例轨迹；
2. 无效样例产生确定性的通用校验失败；
3. 本地序列化与读取不会丢失受支持数据；
4. 能对读回数据集进行基础检查/统计。

## 实现前需决定的事项

- 确认 Episode（或替代物）为 v0.1 持久化/交换单元。
- 选择最小标识、生命周期/终止语义与时间顺序契约。
- 选择扩展与元数据命名空间策略。
- 设定 v0.1 媒体载荷与引用的边界。
- 选择最小序列化信封及兼容性策略。
