# 规范 002：数据集策展与血缘

[English](002-dataset-curation-and-lineage.md)

**状态：** 提议中——架构评审前不作为实现依据。

## 范围

将可复现数据集定义为由选定 Experience 与派生资产组成、具名且版本化的快照；定义快照到来源 Experience、标注、质量报告和选择规则的血缘关系。

## 要求

- 数据集快照有稳定身份、版本、创建上下文、不可变成员清单和声明用途。
- 成员由显式、版本化的策展规则或可审计人工决定选择，不能是不可追溯且可变的查询。
- 快照记录对输入 Experience、标注/质量版本的引用，以及可用时的排除项和原因。
- 选择可表达任务/上下文、模态可用性、质量证据、覆盖分层和失败驱动标准，但 v0.1 不强制这些字段。
- 血缘必须使读者能回答：包含了什么、为什么包含、使用了哪些输入版本，以及两个快照之间改变了什么。

## 非目标

- 数据湖、注册服务、分布式查询引擎、可视化策展 UI 或访问控制系统。
- 自动数据混合优化、通用质量评分或自动去重。

## 验收标准

获批后的本地实现能从 Mock Experience 创建两个数据集快照，通过清单复现第一个快照，解释成员关系，并报告二者的结构化差异。

## 待决定事项

- 规范标识符/引用格式与快照清单格式。
- 成员是否有序，以及如何引用大型媒体资产。
- 人工策展决定与排除原因的最小表示。
