# 数据生命周期：标注、质检、评测与反馈

[English](data-lifecycle.md)

## 目的

Domena 将使 Experience 有用所需的信息——而非仅原始轨迹——视为带有溯源的数据资产。本文定义将采集连接至可度量改进闭环的边界。

```text
Experience → 结构校验 → 质量评估 / 标注 → 策展数据集
     ↑                                      ↓
定向采集 ← 失败分析 ← 评测证据 ← 模型或策略评测
```

## 数据标注

标注是附着于声明目标的语义信息：Episode、时间范围、Step、模态或派生产物。其契约须识别目标、Schema/版本、生产者（人工、规则或模型）、有意义时的置信度及审查状态。标注不是来源元数据，且不得修改原始 Experience。v0.1 仅预留关联与溯源要求。

## 数据质检

质量是与用途相关的证据，区别于结构有效性。质量报告可衡量完整性、时间对齐、传感器健康、覆盖度/多样性、重复性、安全或流程合规性以及标注一致性。规则必须声明版本、输入、阈值、结果与证据。Domena 应支持附加质量报告，但不假定存在通用质量分数。

## 评测与失败分析

评测将某个模型或策略版本同定义的任务、条件、指标定义和数据集/评测集版本对照。结果需要可复现上下文，并可引用单个 Episode 或片段作为证据。失败案例按可修订的假设聚合证据：数据、感知、策略/控制、硬件、环境或采集流程；在调查前不得宣称因果。

## 数据闭环

反馈建议将观察到的失败或覆盖缺口连接到可执行的下一步：采集某种条件、增加或复核标注、修改策展标准，或新增质量规则。它记录输入证据与结果，使项目可衡量某次干预是否改善后续评测。Domena 初期只建模这种关联，不自动决策或运营实体采集。

## 原则与开放问题

- 每个派生资产都需要稳定身份、版本、溯源以及对输入的引用。
- 原始来源数据摄取后不可变；派生数据以新增、版本化方式存在。
- 质量、标注和评测可以彼此不一致；分歧是证据，而非改写历史的理由。
- 开放问题包括目标引用粒度、通用分类体系、审查工作流、数据集/模型版本标识符，以及真实机器人数据的隐私与安全治理。
