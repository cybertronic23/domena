# 经验模型

[English](experience-model.md)

## 工作词汇

**Experience（经验）** 是智能体或机器人与环境交互的领域层记录。它刻意宽于文件、行或消息；根据后续工作流，它可能覆盖一个完整运行、多个运行组成的集合，或一个数据血缘单元。

**Episode（回合）** 是候选的、有边界的交互轨迹：拥有开始与结束，通常可独立处理。它是首个持久化数据边界的首选候选，但尚未是最终决定。

**Step（步骤）** 是 Episode 内候选的有序交互单元，表示来源定义或规范化时间边界上的观察/动作转移。不能假设 Step 具有通用固定张量形状或采样频率。

Step 的拟议组成如下：

| 概念 | 边界 |
| --- | --- |
| Observation（观察） | 决策点可提供给智能体的信息：传感器、图像、本体感觉和派生输入。 |
| Action（动作） | 为转移选择或应用的命令；来源可提供时，需区分预期动作与实际执行动作。 |
| State（状态） | 用于回放、诊断或溯源的环境/机器人状态，不一定暴露给智能体。 |
| Feedback（反馈） | 转移结果，如奖励、成功/失败、终止信号和来源诊断。 |

这些是语义分类，尚不是必需的 Python 字段或 Pydantic 模型。某个模态可以缺失、异步、外部存储或表示为引用。

## 当前已记录的决定

- Experience 是一等词汇并指导所有层；尚未定义为单一可持久化实体。
- Domena 必须支持 RGB、深度、视频、点云、本体感觉、关节/机器人状态、动作、奖励、结果、时间戳及任意元数据等多模态数据。
- 来源特有结构在适配器边界转换，不定义核心模型。
- 模型必须支持扩展，且不假定所有未来模态都属于固定类层次结构。
- 校验必须区分通用结构不变量与来源/任务特有质量规则。

## 开放问题

1. Episode 是否是 v0.1 存储/交换边界，哪些工作流需要更大的 Experience 分组？
2. 最小通用时间契约是什么：每步顺序、物理时间戳、来源时钟，还是全部？
3. 如何把异步模态与变频传感器关联至决策步骤？
4. 最小通用 Episode 的必填字段与可选扩展数据分别是什么？
5. 媒体如何寻址：内联、内容寻址资产、URI 引用，还是混合？
6. 如何区分请求、发送和实际执行的动作？
7. 哪些结果信号可以泛化，而不混淆环境终止、任务成功、安全中断与采集失败？
8. 任意元数据如何命名空间化、版本化和校验？

经验 Schema 规范会在实现前将这些问题收敛为范围明确的 v0.1 决定。
